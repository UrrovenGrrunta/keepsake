# Keepsake — roadmap

Актуально на: **28 сентября 2026**

Репозиторий: <https://github.com/UrrovenGrrunta/keepsake>

## Легенда

- `[x] DONE` — реализовано и проверено.
- `[>] NEXT` — следующий маленький шаг.
- `[ ] TODO` — запланировано.
- `[~] LATER` — отложено до подходящего этапа.
- `[?] DECISION` — решение пока не принято.

Статус `DONE` означает состояние репозитория на дату выше. Если код изменился, сначала сверяем roadmap с `main`.

## Правила разработки

- Проект пишет в основном Timur; ассистент помогает как второй программист и тимлид.
- Готовый код даётся только по явной просьбе. Исключение уже сделано для SQLite слоя.
- Работаем маленькими шагами и не строим инфраструктуру «на всякий случай».
- Значимые правила домена и хранения покрываем тестами. Тривиальные optional поля отдельно не тестируем.
- Пользовательские данные лежат локально в `data/` и не попадают в Git.
- Сначала рабочая основа, затем GUI, Spotify и визуальная магия.

- [x] DONE `initialize_database(connection)` создаёт и обновляет схему.
- [x] DONE Созданы таблицы для photos, people, relationships, events, event participants, journal entries и journal blocks.

- [x] DONE `atomic_write(connection)` использует savepoint.
- [x] DONE Одна операция репозитория атомарна.
- [x] DONE Несколько операций могут участвовать во внешней транзакции вызывающего кода.
- [x] DONE Проверены rollback при ошибке и rollback внешней транзакции.

### Репозитории

- [x] DONE Photo: save, get, list, update, delete.

### Целостность данных

## Что намеренно не делаем сейчас

- ORM и большой migration framework.
- Облачную синхронизацию, аккаунты и сервер.
- Отдельный класс для каждого человека.
- EXIF, геолокацию и распознавание людей на фото.
- Сложный dependency injection и слои ради слоёв.
- Spotify до рабочего дневника.
- Полировку до рабочего GUI.
